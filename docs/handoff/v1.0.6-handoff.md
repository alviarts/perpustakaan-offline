### Git authentication caveat (important!)

The session-default git proxy returned `403` for *both* `git push` *and* `git_pr(action=create)` against this repo — neither push nor the built-in PR-creation tool works through the proxy. The workaround that this session used:

1. **Push:** explicit URL with PAT —
   ```bash
   git push "https://x-access-token:${GITHUB_PAT_ALVIARTS}@github.com/alviarts/perpustakaan-offline.git" <branch>
   ```

2. **Open PR:** call the GitHub REST API directly with `urllib.request` and `Authorization: Bearer ${GITHUB_PAT_ALVIARTS}` against `POST /repos/alviarts/perpustakaan-offline/pulls`.

`GITHUB_PAT_ALVIARTS` is a **user-scoped saved secret**, so it is already available in the next session's shell as `$GITHUB_PAT_ALVIARTS`. Do *not* paste the value anywhere; reference it as `${GITHUB_PAT_ALVIARTS}`.

### Known design constraints in #19

- The current `peminjaman_create` Tauri command takes **`bukuIds`** (not `eksemplarIds`). When a user scans an eksemplar in Pinjam mode, `SirkulasiPage` extracts its `bukuId` and sends that — backend then picks an available eksemplar FIFO. If a future bug requires submitting the *exact* scanned eksemplar, you'll need a separate iteration that adds an `eksemplarIds?` field to `peminjaman_create`.
- Mock store (browser dev mode without Tauri) intentionally returns `null` for `resolveEksemplar` / `aktifByEksemplar` because eksemplar state isn't tracked in localStorage. The whole circulation flow is Tauri-only.

1. Bump `apps/desktop/package.json` `"version"` from `1.0.5` → `1.0.6`.
2. Bump `apps/desktop/src-tauri/tauri.conf.json` `"version"` to `1.0.6`.
3. Bump `apps/desktop/src-tauri/Cargo.toml` `[package].version` to `1.0.6`. Run `cargo check` once afterwards so `Cargo.lock` updates.
4. Update `CHANGELOG.md` with a v1.0.6 section. Group entries by feature (#17, #20, #21, #22, #19) — wording can mirror the PR titles.
