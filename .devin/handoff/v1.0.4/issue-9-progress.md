## Background

`v1.0.3` shipped 6 items via PRs #89–#95 (released as
[v1.0.3](https://github.com/alviarts/perpustakaan-offline/releases/tag/v1.0.3)).

deferred because the existing print flow opens the OS print dialog
(`window.print()`) and never produces a result file — so a "folder hasil"

architecture (jsPDF in the WebView + Rust persist + cross-platform open).

## What's already done on this branch

### Rust (`apps/desktop/src-tauri/`)

- New file `src/commands/kta_export.rs`:
  - `kta_export_pdf(app, bytes: Vec<u8>) -> KtaExportResult` — validates
    the payload (non-empty, ≤64 MiB, starts with `%PDF-`), creates
    `<app_data>/exports/` if missing, writes
    `kta-YYYYMMDD-HHMMSS.pdf`, returns
    `{ filename, abs_path, dir_abs_path }` (camelCase via serde).
  - `kta_open_exports_folder(app) -> String` — uses the `opener` crate
    to launch the OS file manager on the exports dir. Returns the
    folder path so the frontend can log it.
  - 5 unit tests in the same module: empty payload, oversize (>64 MiB),
    non-PDF magic, minimal `%PDF-1.7` header, filename pattern.
- `Cargo.toml`: added `opener = "0.7"` (one transitive deps tree).
  Cargo notes 0.8 is available — we pinned 0.7 for license alignment with
  the existing dep set; if the next session wants to bump to 0.8 it
  should be a separate commit with `cargo update -p opener`.
- `Cargo.lock`: regenerated by cargo (committed).
- `src/commands/mod.rs`: added `pub mod kta_export;`.
- `src/lib.rs`: registered both commands in
  `tauri::generate_handler![…]` (right after the existing
  `kta_template_*` block).

### Frontend (`apps/desktop/src/`)

- `package.json`: added `"jspdf": "^2.5.2"` (resolves to 2.5.2 in
  pnpm-lock.yaml; 0 dev-deps — only `qrcode` peer was already present).
  Did NOT install `html2canvas`. The PDF is built directly from
  layout coords, no DOM rasterisation.
- New file `features/kta/pdf.ts`:
  - `buildKtaPdfBytes(input: KtaPdfInput): Promise<Uint8Array>` — ports
    the layout iteration logic from `print.ts` to mm-based jsPDF
    primitives:
    - A4 portrait page, 12 mm margin, 8 mm card gap, grid sized to fit.
    - Per card: `roundedRect` border (dashed slate-400), optional
      background fill, then per-field render of:
      - `foto` → `addImage(dataUrl, 'AUTO', x, y, w, h, undefined, 'FAST')`
        with placeholder slate-200 rect on failure.
      - `qr` → built from `buildQrPayload(memberId)` via the existing
        `qrcode` lib (256 px PNG data URL), added the same way.
      - text fields (`static`, `identitas`, `nama`, `kodeAnggota`,
        `kelas`, `jurusan`, `agama`) — `setFontSize(px * 0.75)`,
        `helvetica` regular/bold, `setTextColor` from hex, alignment
        respected, `maxWidth` clamped to field width.
  - jsPDF `setLineDashPattern` is used for the dashed border. Verified
    to exist on jsPDF 2.5.x; if a future jsPDF major drops it the
    fallback is a solid `roundedRect` (not a blocker).
- `lib/kta.ts`: extended `KtaRpc` with
  - `exportPdf(bytes: Uint8Array) → Promise<KtaExportResult>` →
    `invoke('kta_export_pdf', { bytes: Array.from(bytes) })`. The
    `Array.from` is required because Tauri serialises `Vec<u8>` as
    a JSON number array, not a typed-array; `Uint8Array` over JSON
    becomes `{0:…,1:…}` and breaks deserialisation.
  - `openExportsFolder() → Promise<string>` →
    `invoke('kta_open_exports_folder')`.
  - Browser-mode mock: `exportPdf` triggers a `Blob` download with the
    same `kta-YYYYMMDD-HHMMSS.pdf` name; `openExportsFolder` is a
    no-op that returns `''`. This keeps `pnpm dev` (non-Tauri) usable.
- `features/kta/CetakKtaPage.tsx`:

    always enabled), "Simpan PDF" (outline, disabled until a member +
    template are selected), "Cetak" (existing primary).
  - Persistent emerald ribbon below the header showing the most recent
    export filename + a "Buka Folder Hasil" link. Renders only after a
    successful save.
  - Print toast strings now pull from i18n with sensible fallbacks
    (we used hard-coded Bahasa strings before, and i18n keys already

  - `toast.pdfSaved`, `toast.pdfFailed`, `toast.openFolderFailed`
  - `lastExport.label`

## Architectural notes / non-obvious bits

- **Why no `html2canvas`.** The KTA layout uses `position: absolute`
  with `%` coords inside a fixed-size card. `html2canvas` is brittle
  with that pattern (clips half-overlap children, blows up CSS vars in
  `oklch()` form). jsPDF primitives let us iterate `layout.fields`
  directly and apply the same `%`-of-card math the print HTML uses, so
  the PDF and the print preview stay visually identical.
- **Why no `headless_chrome`/`weasyprint`/`printpdf`.** Bundling
  Chromium adds ~100 MB to the installer and a separate binary the
  Tauri runtime would have to ship. `printpdf` doesn't speak HTML.
  jsPDF is already JS in the WebView — zero new native deps.
- **Why `Vec<u8>` over the wire instead of base64.** Tauri 2 serialises
  `Vec<u8>` as a JSON array of numbers (not base64), and the
  `@tauri-apps/api/core` `invoke` helper handles `Array.from(uint8Array)`
  natively. base64 would add ~33% transfer overhead and need decoding
  on both ends. Tradeoff is gigabyte-class blobs would be expensive,
  but the 64 MiB cap in `kta_export_pdf` keeps that bounded.
- **Why `opener` 0.7 not 0.8.** 0.7.x is what the existing
  Tauri 2.11 / wry stack pulls transitively for some dialog plugins; the
  bumped 0.8 changed its license metadata. Pin matches what's already
  in `Cargo.lock` indirectly. Free to bump after CI proves the lock
  resolution is stable.
- **`%PDF-` magic check is intentional.** It's not anti-virus, it just
  rejects payloads where the frontend code regressed (e.g. someone
  passes raw HTML through `exportPdf` by accident). The 64 MiB cap is
  the actual security floor.
- **Filename uses local time, not UTC.** Indonesia is UTC+7, and the
  user expects file timestamps to match wall-clock when they're
  triaging exports. `chrono::Local::now()` is fine here because we're
  running inside a desktop process tied to the user's locale.
- **No `kta_export_pdf_path` second variant.** We considered exposing
  a "save as" picker via `tauri-plugin-dialog`, but the `<app_data>/exports/`
  layout is what the user asked for ("Buka Folder Hasil"). A future
  v1.0.5 could add an explicit "Save As..." next to "Simpan PDF".
